# Open-Source Software

## Definition

Open-source software is software whose source code is made available under a licence that permits people to inspect, use and modify it. The exact permissions depend on the licence.

Open source does not automatically mean that software has no cost or no restrictions. Users and developers must still follow the licence conditions.

## Advantages

One advantage is transparency. Developers can examine how the software works instead of relying only on the supplier’s description.

Open-source projects may also benefit from community contributions. Different developers can report defects, improve documentation and add new functions. Organisations may adapt the software to meet their own technical requirements.

Another advantage is reduced dependency on a single supplier. If the original developer stops supporting the project, another organisation may continue maintaining the source code. However, this is only realistic when suitable technical knowledge and resources are available.

## Limitations

The availability of source code does not guarantee quality or security. A project may have few maintainers, outdated dependencies or unresolved vulnerabilities. Publicly visible code can be reviewed by defenders, but attackers can examine it as well.

Support may also vary. Some projects provide active communities and commercial support, while others depend on a small number of volunteers. An organisation should therefore examine the project’s maintenance history, documentation and update process before adopting it.

## Security Considerations

Open-source components should be recorded in a software inventory. This helps an organisation identify where a vulnerable library is being used when a security issue is announced.

Important controls include:

- Reviewing the software licence
- Checking the project’s update history
- Monitoring known vulnerabilities
- Installing security patches
- Removing unused dependencies
- Testing updates before deployment

Responsibility remains with the organisation using the software. A publicly available component should not be trusted automatically.

## Open Source and Proprietary Software

Proprietary software normally keeps its source code under the control of a company or owner. Customers receive permission to use the software according to a licence but may not be allowed to modify its code.

Proprietary software may provide formal vendor support and clear responsibility for updates. Its limitations can include licence costs, restricted customisation and dependence on the supplier.

The better choice depends on the project. An organisation should compare security support, cost, compatibility, licensing and internal expertise instead of assuming that one model is always better.

## Summary

Open-source software can provide transparency, flexibility and opportunities for collaboration. Its risks include inconsistent maintenance, licensing problems and vulnerable dependencies. Safe adoption requires technical evaluation and continued monitoring rather than trust based only on the availability of the source code.
